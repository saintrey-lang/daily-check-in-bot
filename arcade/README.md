# Golden Spatula Arcade Discord Activity

The existing Next.js arcade is served inside Discord as an Activity. With `DISCORD_CLIENT_SECRET` configured, the Activity requests Discord's `identify` authorization and uses the verified Discord username as the player name. A new player links a Golden Spatula Game ID once, with no name or password form. A player with an older `ArcadePlayers` entry enters its old PIN once to reclaim progress. Future Activity launches identify the Discord account and resume without a form. The direct website retains its Name, Game ID, and PIN entry. Each game saves its progress under Game ID in `ArcadeProgress`; the link is saved in `ArcadeDiscordLinks`.

Puzzle choices include the bundled images and image attachments from Discord channel `1573243616925712495`. The bot reads the channel through the Discord API. Images are proxied through `/api/puzzle-image`, so expired Discord attachment URLs do not break a saved puzzle. Images over 4 MB are omitted. The first bundled image remains the first choice.

All crossword and puzzle scores and exit reports post to `1293667554866499676`; puzzle posts include the selected picture. Channel `1573243616925712495` supplies puzzle pictures only. The verified Discord username appears in Activity posts. When the player leaves before finishing, **Exit & Share** posts their current points and saves their work. A `pagehide` beacon also attempts that post when the Discord window closes; Discord and mobile browsers do not guarantee a close event, so use the button when the post must arrive.

## Developer Portal setup

1. In the Discord Developer Portal, open the application whose bot token is configured as `DISCORD_BOT_TOKEN` on the `golden-spatula-arcade` Vercel project. Under **Activities → URL Mappings**, map `/` to `golden-spatula-arcade.vercel.app`. Enable the Activity in **Activities → Settings**. The app's launch entry point appears in Discord after Activities are enabled.
2. Grant that bot **View Channel** and **Read Message History** in puzzle picture channel `1573243616925712495`. It needs **View Channel**, **Send Messages**, and **Embed Links** in score channel `1293667554866499676`.
3. In the Discord app's **OAuth2** settings, add a Redirect URI if none exists. Add its Client Secret as `DISCORD_CLIENT_SECRET` in the `golden-spatula-arcade` Vercel project's Production environment, then redeploy. Treat the secret as confidential; never add it to GitHub. The OAuth flow uses only `identify`. If the secret is absent, the Activity retains the older Name/Game ID/PIN entry, so an incomplete setup does not interrupt play.
4. Ensure the Vercel arcade project retains `DISCORD_BOT_TOKEN`, `CHECKIN_GOOGLE_SHEET_ID`, `GOOGLE_SERVICE_ACCOUNT_EMAIL`, `GOOGLE_PRIVATE_KEY`, `ARCADE_PIN_PEPPER`, and `ARCADE_SIGNING_SECRET`. `DISCORD_APPLICATION_ID` may be added; if absent, the app derives the public ID from the bot token. The service account must be an Editor on the Sheet. The arcade creates `ArcadeDiscordLinks` for Discord identities and `ArcadeProgress` for game state, and retains the existing player records.
5. Launch the app in a Discord voice or text channel using its Activity entry point. Allow `identify`, link a Game ID, test a partial move and **Exit & Share**, reopen the game, and submit a completed score. Discord may restrict an unverified Activity to its developers and testers in small servers; verification is needed for broad community launch.

The arcade's Vercel site remains the server and image host. The player-facing game launches as the Discord pop-up. No bot token is sent to the browser.
